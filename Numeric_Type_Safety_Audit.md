# Numeric and Text Type-Safety Audit

Date: 2026-10-20

## Objective

Prevent worksheet text from being silently treated as missing numerical data, prevent
accidental string arithmetic, and prevent an operation from leaving a column's stored
values inconsistent with its declared metadata type.

The governing rule is: blanks may be omitted where an algorithm allows missing data,
but a nonblank value that cannot be converted to a number must produce a row-specific
error before the source or destination dataset is modified.

## Findings and corrections

| Boundary | Failure found | Correction |
| --- | --- | --- |
| Formula inputs | Numeric strings in an object column reached NumPy as text; mixed text could also cause string repetition such as `col1 * 2`. | Wholly numeric object columns are promoted for formulas. Numerical expressions that produce text now fail with a row/example message, while deliberate text expressions remain possible. |
| Formula outputs | A formula could write text into a Numeric/Scientific destination or numbers inconsistently into a Text destination. | Existing target metadata is validated before assignment. Numeric targets reject text atomically; Text targets receive strings. The same check is used for sequential and worker/batch results. |
| Fill Range | A numeric fill could leave object storage or stale Text/Auto metadata, and partial fills could hide unreplaced text. | The complete candidate column is validated before mutation, stored as `float64`, and marked Numeric. Unreplaced nonblank text aborts the operation without creating undo history. |
| Scientific engines | Auto/object columns were converted with `errors="coerce"`; invalid text could be dropped as though it were blank. | Calculus, FFT, smoothing, interpolation, fitting, peak/Raman inputs, and multi-column statistics now reject every nonblank nonnumeric cell, including Auto columns. |
| Statistics | Direct single/pair/group statistics could silently discard text while aligning or dropping missing rows. | Public statistics inputs now validate nonblank cells before missing-value handling. |
| Plotting | Numeric plot roles could omit bad cells from Auto columns and still draw a plausible but incomplete graph. | Numeric plot inputs now fail with the visible row and example value. Text/category axes remain supported. |
| Data preparation | Mean/median/interpolation, numeric filters, grouping, and binning silently coerced text to missing. A custom missing-value fill could turn a numeric column into text. | Numeric data-prep paths use strict conversion and respect Text metadata. Custom fill values must be numeric for explicit, dtype-based, or safely inferred numeric columns. |
| Metadata-preserving paste | Whole-column paste could accept invalid text with Numeric metadata and could partially insert earlier columns before a later column failed. | Every incoming column is normalized and validated before history capture or mutation; the frame, formulas, and metadata commit together. |
| Raman maps and previews | Map X/Y and per-spectrum values were converted in several UI paths before a shared validity check. | Preview and batch/map execution validate X, Y, spectral X, and signal columns before array conversion. |
| Numeric column suggestions | Auto columns with a few numeric cells and some text could be offered as valid numeric ranges. | Suggested numeric ranges now exclude any column containing nonblank nonnumeric cells. |

## Verification

formulas, metadata targets, plots, statistics, calculus, smoothing, interpolation,

## Residual risks and follow-up

- The audit covers every current `pandas.to_numeric(..., errors="coerce")` use. Some
  occurrences consume values generated by JASC itself (fit curves and summary metrics);
  these are intentionally tolerant because their user-data inputs are validated
  upstream.
- Import inference remains deliberately all-or-nothing per column: wholly numeric text
  becomes numeric, while mixed content remains text/object and will be rejected if later
  selected for a numerical role.
- New numerical features should use the shared validation boundary rather than adding a
  raw coercion followed by `dropna()`.
- Property-based fuzzing for extension dtypes, localized numeric strings, infinities,
  and unusual pandas indexes would be a useful additional verification layer, but no
  unresolved data-loss defect was found in the audited paths.
